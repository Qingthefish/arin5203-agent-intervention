\section{Motivation and Research Question}

Long-running tool-using agents shorten histories to control context length,
latency, and cost. This compaction is lossy: a summary may retain the current
goal while dropping an approval boundary, prohibition, expiry, entity, amount,
or recovery condition that determines whether a later tool call is safe.
Governance Decay shows that constraints obeyed in full context can be omitted
by compaction and then violated~\cite{chen2026governance}. U-Fold instead
separates an evolving intent summary from a task-relevant tool log and improves
long-context tool use~\cite{su2026ufold}. These results make context management
an operational control problem, not only a token-saving problem.

We ask: \emph{under a fixed context budget, can loss or ambiguity of
action-critical evidence be detected after compaction and used, before a
state-changing tool call, to choose Execute, Confirm, or Handoff?} Execute
requires visible, mutually consistent authority and recovery evidence. Confirm
is appropriate when one short human answer can repair an omission. Handoff is
reserved for policy conflict, non-recoverable impact, or uncertainty that a
single answer cannot resolve. Our contribution is not another general-purpose
compressor. It is an intervention layer connecting compaction failures to
action-time control, evaluated through observable state transitions.

$\tau$-bench and ToolSandbox motivate stateful, tool-level evaluation
~\cite{yao2024tau,lu2025toolsandbox}; SABER motivates verification at mutating
steps~\cite{cuadron2025saber}. ACON and StateComp study how and when to compact
efficiently~\cite{kang2026acon,wang2026statecomp}. We instead test what should
happen when the resulting working context no longer supports a consequential
action.

\section{Benchmark and Method}

The planned benchmark has 20 base scenarios in one deterministic AI-platform
simulator, covering quota changes, workload preemption, resource transfer,
model rollout, and capacity reclamation. Platform approval and rollback,
financial-style entity/amount/validity, and main--sub-agent authority patterns
are evidence templates inside the same simulator, rather than three unrelated
products. Each base scenario yields three matched contexts: complete evidence,
one action-critical record removed, and similar-length irrelevant noise
removed. Siblings stay in one split. Scenario identifiers, deletion condition,
gold route, and oracle-only facts never enter the model prompt.

Figure~\ref{fig:pipeline} shows the evaluation chain. A compaction strategy
produces active context under a common budget. A structured audit checks target
entity, requested scale or amount, authority scope, validity or expiry,
negative constraints, and reversibility or recovery. The intervention gate
then routes the proposed mutation. A deterministic simulator applies only
executed calls, and a private state-transition oracle records whether the call
was prohibited, whether state changed, and whether the task completed. For a
Confirm case, the simulator injects the specified human answer and re-evaluates
the same action; Handoff must retain residual risk after that replay.

Baselines are full history, recent-window truncation, generic LLM summary,
precise constraint pinning, and a U-Fold-inspired intent-summary-plus-tool-log
method. The proposed policy adds the structured post-compaction audit and
three-way intervention. We will report harmful-mutation rate, safe autonomous
completion, critical-evidence retention, intervention accuracy, review burden,
context reduction, latency, and tokens. Any thresholds are selected on
development families and frozen before the held-out test. ``Verify every
mutation'' and one prompted critic remain action-level baselines, but the main
comparison concerns context strategies at similar retained budgets.

\section{Preliminary Evidence}

We first ran a six-scenario alignment pilot using local Qwen3.5-9B through
Ollama. Five context strategies produced 42 measured generations plus one
warm-up, with zero format failures and zero external API cost. As
Table~\ref{tab:pilot} shows, generic summarization was a strong baseline: it
reduced the estimated context by 84.4\% while preserving all six route
decisions. The broad keyword pinning rule retained almost everything yet still
misrouted two cases. Selective context management requested review twice but
received no answer, so this run does not establish incremental HITL value.

A later re-audit used the exact raw tokenizer of the same Qwen model on all 55
saved active contexts. Excluding the full-history ceiling, the largest-to-smallest
mean context ratio was 6.23x in the five-case pilot and 5.90x in the six-case
pilot, far above a pre-specified 1.10 budget-matching limit. The character-count
proxy also had 9.1\% mean absolute ratio error and 18.3\% maximum error. Thus
Table~\ref{tab:pilot} is feasibility evidence and cannot rank compaction methods.

We then specified a causal anti-shortcut development gate over six families and three
matched contexts per family. The first implementation was stopped before any
measured output because condition-specific event IDs, unmatched positions, and
different sibling seeds could reveal the treatment. In the revised design,
critical evidence and matched noise use the same role, adjacent positions,
similar token mass, neutral IDs, and one seed per family.

The revised audit completed 18 local generations in 110.1 seconds, consuming
15,213 input and 800 output tokens with zero format errors and zero API cost.
All six full-evidence contexts were routed to Execute, and removing matched
noise changed none of the six decisions. Removing critical evidence triggered
Confirm in four of six families, meeting the minimum pre-specified development
threshold. This check establishes whether deletion stops autonomous execution;
it does not yet establish whether the missing evidence is answerable by Confirm
or requires Handoff. Both
main--sub-agent families still executed after authority and recovery evidence
was removed. Thus the pilot supports a causal dependence on critical evidence
for platform and financial patterns, but also identifies delegated-authority
reasoning as a concrete failure mode. It does not demonstrate safety
superiority or generalization.

To separate Confirm from Handoff, a second development pilot used nine
scenarios and six paired follow-ups. Confirm meant that one authenticated
response from a pre-identified authority was sufficient for automatic resume;
Handoff meant that a policy conflict required independent adjudication. All
nine initial routes were correct, all three Confirm cases became Execute after
the authorized response, and all three Handoff cases remained Handoff after an
ordinary requester replied. The 15 calls took 73.8 seconds, used 8,503 input
and 572 output tokens, and cost no API fee. However, a post-hoc independent
review found four contradicted and one unsupported reason code among 41; in two
cases the model claimed that recovery was unavailable although a verified
recovery record was visible. Thus correct routing does not establish faithful
use of evidence. This rationale count is exploratory, not a pre-specified
metric.

We next replaced free-form reasons with a closed eight-factor ontology and
mandatory event citations. The first runner completed all calls but failed in
post-run auditing because an in-memory tuple was not accepted as a JSON-style
list; its raw trace and failed manifest were preserved. In the repaired v2
gate, route accuracy remained 15/15 but only 7/15 records achieved joint
grounded route correctness. Two pre-committed development revisions improved
the citation interface without changing the route labels. The final, frozen v4
prompt again routed 15/15 correctly with zero harmful false executes and zero
directly contradictory factor claims. Grounding precision reached 93.9\%, but
decisive-factor recall was 86.1\% and joint accuracy remained 10/15, below the
pre-specified 90\% recall and 13/15 joint thresholds. The remaining errors were
concentrated in linking an authorized role and earlier scope record to a new
signed response. We therefore did not proceed to the larger comparison.

The final exact-budget development gate used nine new bases and three matched
siblings per base: full evidence, one action-critical deletion, and one
length-matched noise deletion. Seven context conditions were compared over 27
contexts. Every compacted memory used at least 90\% of a 384-token raw Qwen
budget, while full history remained an unbudgeted ceiling. The final v6 run
completed 81 compactor and 189 router generations in 82.9 minutes with zero
external API cost. All 189 records passed the budget, provenance, label
blinding, fill, and output-format contracts. On the 18 stable full/noise
siblings, typed proof retention plus deterministic audit preserved every
visible critical card and routed 18/18 correctly, with zero harmful executions,
zero unnecessary interventions, and zero noise-induced route changes. The
unaudited router reached 14/18 and made four harmful executions. Across all 27
typed contexts, the audit remained 24/27 because the three active-hold events
deleted before compaction cannot be recovered. Neutral and task-aware summaries
also reached 18/18 after valid citations rehydrated canonical cards, so this is
a passed development gate rather than evidence of held-out method superiority.

\section{Next Stage and Limitations}

The development method, prompts, budget, validator, thresholds, and metric
implementation are now frozen. We will author 11 untouched held-out bases and
their 33 matched siblings, keeping all siblings from one base in the same split,
then run the comparison once. These cases complete the proposal's 20-base,
60-context design. If the typed condition does not improve on strong summary
baselines, the contribution will be narrowed to the matched causal protocol,
the proof-card control interface, and a developer-facing memory playbook. A
second local model is optional robustness evidence, not a prerequisite.

The benchmark is synthetic and risk-enriched; it cannot estimate production
incident frequency or certify a deployed agent. Current results use one local
model and one generation per context. The early table uses a proxy, while the
new pipeline enforces an exact target-model raw-token budget. Active
context may omit data that remains recoverable from an external checkpoint.
Human review also has real cost, so unnecessary Confirm
and Handoff decisions will be reported rather than treated as automatically
safe. Negative or null results will narrow the contribution instead of being
hidden.
