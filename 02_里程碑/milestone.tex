\section{Motivation and Research Question}

Imagine a travel Agent asked to change a flight and charge a company card. It
still remembers the requested itinerary, but an earlier delegation limit or a
later policy hold has disappeared from its shortened history. The next message
can remain fluent while the booking state changes incorrectly. This is the
failure we study: not whether a summary reads well, but whether the Agent can
still prove that its next tool action is allowed.

Long-running tool-using Agents compact histories to control length, latency,
and cost. Governance Decay shows that obeyed constraints can disappear during
compaction and later be violated~\cite{chen2026governance}. U-Fold separates
an intent summary from a task-relevant tool log~\cite{su2026ufold}; ACON and
StateComp study how and when to compress~\cite{kang2026acon,wang2026statecomp}.
We instead ask what should happen when the result no longer supports an action.

We ask: \emph{under a fixed raw-token budget, can a post-compaction evidence
audit reliably choose Execute, Confirm, or Handoff before a state-changing
tool call?} Execute requires valid proof; Confirm means one authenticated
answer can repair the gap; Handoff transfers an authority conflict or residual
risk. Our contribution is a causal test and proof interface connecting memory
loss to action control and observable state change, not another compressor.

\section{Data, Method, and Evaluation}

The benchmark contains 20 bases and 60 matched contexts in one deterministic
state-transition harness: nine development bases and 11 held-out bases authored
after the method freeze. Platform, financial, and delegated travel templates
each yield (i) complete evidence, (ii) one critical event removed, and (iii) an
equal-length, same-role noise event removed. Siblings stay in one split;
neutral IDs, matched positions, and one family seed hide the treatment. Gold
routes and oracle-only facts never enter a prompt.

Figure~\ref{fig:pipeline} shows the chain. Each strategy produces memory under
a 384-token raw Qwen budget. Ours retains proof cards with source, kind, actor,
target, scope, and validity. A deterministic audit checks authority, scope,
expiry, blockers, and recovery, then routes the mutation. The simulator applies
only executed calls; a private oracle records the state diff and prohibition.
One authenticated answer can resume Confirm, while an ordinary requester
cannot resolve Handoff.

Baselines are full history, recent window, neutral and task-aware summaries,
generic pinning, and U-Fold-lite. Method labels are blinded and budgets matched.
We score the direct router and the same memory after audit using route, harmful
Execute, unnecessary intervention, safe autonomy, proof retention, and citation
precision. Budget, format, source integrity, blinding, and matched-noise
stability are protocol checks. $\tau$-bench and ToolSandbox motivate stateful
tool evaluation~\cite{yao2024tau,lu2025toolsandbox}; SABER motivates checks at
mutating steps~\cite{cuadron2025saber}.

\section{Protocol Lessons and Development}

Early pilots ran successfully, but a re-audit found 5.90--6.23x differences in
mean compacted size, invalidating their method ranking. A grounded gate later
selected 15/15 routes correctly, yet only 10/15 paired the route with complete
decisive evidence; one asserted an absent approval. Route accuracy alone was
therefore insufficient.

On identical contexts, a generic critic spoiled three of four correct direct
decisions, a candidate-visible critic retained both harmful Executes, and a
blind verifier once treated policy clearance as authority. These failures
motivated typed proof and deterministic obligation checks instead of another
free-text reviewer.

The repaired exact-budget development run used nine new bases and 27 siblings.
Its v6 completed 270 generations in 82.9 minutes at zero API cost; all 189
scored records passed budget and provenance contracts. Typed memory plus audit
reached 18/18 stable routes versus 14/18 direct, without harmful Executes or
unnecessary intervention. Strong summaries also reached 18/18 after valid
citations rehydrated proof cards. We froze data, prompts, budget, validator,
thresholds, and metrics before creating held-out cases.

\section{Held-Out Result and Boundary}

We authored 11 held-out bases and 33 siblings after the freeze, then ran once.
Local Qwen3.5-9B completed 330 generations in 103.2 minutes at zero API cost;
all 231 scored records passed every protocol contract. On 22 stable complete
and matched-noise contexts, typed memory plus audit preserved every visible
card and critical event, routed 22/22, retained all eligible autonomy, and
caused no harmful Execute, unnecessary intervention, or noise-induced change.
It corrected 10 direct-router errors and spoiled none.

Table~\ref{tab:heldout} prevents an overclaim: three strong baselines also tied
at 22/22 after audit. Typed memory's clearest advantage was inspectability.
All eight repairable proof deletions failed closed, but all three active holds
removed \emph{before} compaction still executed harmfully. Audit can validate
visible proof; it cannot invent an unseen prohibition.

\section{Outputs, Limitations, and Next Stage}

The outputs are a matched causal memory test, a typed proof interface, and an
Agent Memory Playbook. A deterministic replay exposes memory, cited proof,
route, and state diff from frozen traces. The takeaway is to define action
proof first; store it with provenance; compact conversation and proof
separately; revalidate at the tool boundary; distinguish repairable from
operator-only gaps; and compare critical with equal-size noise deletion.

The synthetic, risk-enriched benchmark uses one local model and one generation
per context, so it cannot certify production safety. Hidden holds require an
upstream durable store, checkpoint, or independent monitor. We will not tune or
rerun held-out data; remaining work is the report, demo, and presentation.
