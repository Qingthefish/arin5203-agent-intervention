\section{Introduction}

Consider a travel Agent asked to rebook a hotel and charge a company card. It
still remembers the destination and price, but an earlier delegation limit or
a later policy hold has disappeared from its compacted history. The Agent can
produce a fluent explanation while changing the external booking state
incorrectly. This motivates our project: context quality should be evaluated
by the evidence available for the \emph{next action}, not only by whether a
summary appears coherent.

Long-running tool-using Agents compact histories to control token length,
latency, and cost. Governance Decay shows that previously obeyed constraints
can disappear and later be violated~\cite{chen2026governance}. U-Fold separates
an intent summary from a task-relevant tool log~\cite{su2026ufold}; ACON and
StateComp study how and when to compress~\cite{kang2026acon,wang2026statecomp}.
Compaction Cliff already combines typed retention and verification;
PAIR uses same-state counterfactual continuations~\cite{zerhoudi2026cliff,min2026pair}.
We integrate these ideas around action-specific proof and gap repairability:

\begin{quote}
\emph{Under a fixed raw-token budget, can a post-compaction evidence audit
more reliably choose Execute, Confirm, or Handoff before a state-changing
tool call?}
\end{quote}

Execute requires visible valid proof. Confirm means one authenticated answer
can repair the gap. Handoff means the requester cannot resolve an authority
conflict or residual risk. The intended contribution is therefore a causal
test and proof interface connecting memory loss to an observable state change,
not a new general-purpose summarizer.

\section{Problem Statement and Data}

Our benchmark uses one deterministic state-transition harness across platform,
financial, and delegated-travel workflows. Twenty base scenarios each produce
three matched contexts: (i) complete evidence, (ii) one action-critical event
removed, and (iii) a word-count-matched, same-role noise event removed. This yields
60 contexts. Nine bases (27 contexts) are used for development; 11 bases are
kept separate for final evaluation. Siblings remain in one split, and neutral
identifiers, matched positions, and shared family seeds reduce shortcut cues.
Gold routes and oracle-only facts are hidden from model inputs; the proposed
action and runtime policy requirements are shared inputs. Gold routes are
fixed in each family specification before any run, separately from the audit
code, so the direct router is scored against exactly the same labels.

The matched design distinguishes loss of meaning from loss of text. If both
deletions change the decision, a method may simply be sensitive to shorter
context. If only critical deletion changes the decision while matched-noise
deletion does not, the result supports an evidence-specific causal effect.

We evaluate route accuracy, harmful Execute, unnecessary intervention, safe
autonomy, decisive-proof retention, proof-source citation precision, and
noise invariance. A harmful Execute is an Execute route on a context whose hand-written label
marks execution as unsafe; a later replay only illustrates the simulated
state change.

Stateful tool evaluation follows the
motivation of $\tau$-bench and ToolSandbox~\cite{yao2024tau,lu2025toolsandbox};
SABER motivates checking mutating steps rather than judging only the final
response~\cite{cuadron2025saber}.

\section{Technical Approach}

Figure~\ref{fig:pipeline} shows the current pipeline. Full history is an
unbudgeted reference. Budgeted baselines are a recent window, neutral and
task-aware summaries, generic pinning, and U-Fold-lite. Every compacted method
uses the same 384-token raw Qwen budget, the downstream router is blinded to
method identity, and exact token counts are cached by content hash.

Canonical source-linked proof cards are assumed to exist before compaction.
Memory keeps compact records or source IDs; for every source ID that survives,
the audit looks up the full card and checks its issuer, subject, target, scope,
and validity. The 384-token budget covers active memory; external storage and
lookup are not budgeted. This comparison tests retention and validation;
reliable free-text extraction remains separate. Confirm denotes a gap one
authenticated answer can repair; an ordinary requester cannot resolve Handoff.

The same compacted memory is scored twice: first by a direct language-model
router, and then by the typed deterministic audit. This isolates the audit's
incremental value from the compressor. Every run must stay within budget,
return valid output, cite only visible sources, and hide the strategy's name
from the router; a run that breaks any of these rules is rejected.

\section{Intermediate Results}

Three development findings changed our design. First, an exact tokenizer
re-audit found 5.90--6.23$\times$ differences in mean compacted length across
early methods. Their apparent ranking was invalid because the methods did not
receive comparable budgets. Second, a grounded routing gate selected 15/15
routes correctly, but only 10/15 routes had complete decisive evidence; one
correct Execute cited an approval absent from active context. Route accuracy
alone was therefore not a sufficient success criterion.

Third, free-text review did not reliably fix the problem. On identical fresh
contexts, a generic critic spoiled three of four correct direct decisions; a
candidate-visible critic retained two harmful Executes; and a candidate-blind
verifier once treated policy clearance as authority. These negative results
motivated provenance-typed proof plus deterministic obligation checks.

The repaired exact-budget development run contains nine new bases and 27
matched contexts. Local Qwen3.5-9B completed 270 measured generations in 82.9
minutes with zero external API cost. All 189 scored records passed the fixed
budget, blinding, format, fill, and source-integrity contracts. Table~\ref{tab:dev}
reports the 18 stable complete and matched-noise contexts used for method
selection. With the audit, every strategy's harmful Executes fall to zero, but
strategies that lose positive proof (recent window, generic pinning) also lose
all safe autonomy: the audit is only as good as the card recall of the memory
it reads.

Typed proof with the audit reached 18/18 stable routes and retained all
eligible autonomous executions in that subset. Strong summaries also reached
18/18 after valid citations rehydrated canonical proof records. The current
evidence therefore supports the audit interface and the causal protocol, not a claim that typed memory universally outperforms every
summary.

\paragraph{Frozen held-out evaluation.}
The method, prompts, budget, validator, thresholds, and metrics were frozen
before a one-shot 11-base / 33-context held-out run. Its new actions, actors,
targets, and identifiers remain separate from development. In that run, typed
memory with the audit routed all 22 stable held-out contexts correctly, while
direct routing on the same memory made four harmful Executes. Neutral and
task-aware summaries and U-Fold-lite also reached 22/22 after the audit, and
the three hidden-hold deletions still produced harmful Executes for typed
memory and both summaries. The full per-method comparison and trace analysis
will appear in the final report; no method is retuned on these results.

\paragraph{Post-hoc analyses of the frozen traces (no model calls).}
\emph{Paired tests.} On held-out typed memory the audit fixed 10 routes and
broke none. To account for related siblings, an exact family-clustered sign-flip
test gives $p{=}0.031$, or $0.094$ after Holm correction over seven strategies.
Neutral and task-aware summaries and U-Fold-lite gained 17--19 correct routes
with none lost (family-level Holm $p{\le}0.017$). Harm reductions did not reach
family-level significance. Only six held-out families are unsafe to execute,
limiting the resolution of this two-sided sign-flip test; additional independent
families would be needed for stronger evidence.
\emph{Failure taxonomy.} 113 of 135 held-out direct-route errors were too
permissive; in 17 of them an active hold was present in memory and the model
still chose Execute.
\emph{Hold re-read.} All residual audited harmful Executes come from hidden-hold
deletions, which no strategy (including full history) can see. Replaying the
audit first reproduces all 420 frozen decisions across development and held-out
contexts. Adding a simulated pre-commit hold-registry lookup then removes every
residual harmful Execute (33/33 held-out routes correct for full history, both
summaries, U-Fold-lite, and typed memory) without increasing unnecessary
interventions. Necessary Handoffs replace harmful Executes. This deterministic
design check assumes an authenticated hold registry; it is not a live-system
or new model result.


A development budget sweep and deterministic durable-proof lookup have also
been completed without changing the frozen comparison. The latter addresses
blockers missing \emph{before} compaction. A separate frozen development-only
free-text extraction diagnostic released only Handoff, withholding every
eligible Execute. It does not establish reliable upstream card creation.
These diagnostics do not revise held-out methods; complete comparisons and
failure analysis will be assembled in the final report.

\paragraph{Post-hoc 2$\times$2 router ablation (new model calls).}
We re-routed every frozen held-out memory three more ways (693 calls, all
parsed; temperature 0, seed 5203; Colab T4, Qwen3.5-9B build
\texttt{56671c2ab}, which differs from the frozen build): \emph{direct}
re-run as the same-build baseline; \emph{checklist}, where the model fills
obligation statuses from memory and the frozen rule decides; and
\emph{rehydrated}, where the model sees canonical cards but decides itself
(Table~\ref{tab:ablation}). The audit column is deterministic and unchanged.
Relative to the new direct baseline, rehydration raised full-history stable
accuracy from 12/22 to 15/22 and reduced harmful Executes from 16 to 13, but
raised typed-memory harm from 11 to 15. Checklist routing reduced harm for
several strategies and improved full-history stable accuracy to 16/22, while
neutral-summary stable accuracy fell from 10/22 to 8/22. Thus both effects
depend on the memory strategy. Cards plus deterministic validation reached
22/22 stable routes for five strategies; recent window and generic pinning
remained at 6/22. All residual audited harmful Executes came from hidden holds.
Errors in model-extracted obligation statuses are a hypothesis for follow-up
analysis, not an established cause of every checklist failure.

\section{Final-Stage Plan and Limitations}

Before the final report, we will prioritize a blind review of a label subset
by a team member who did not implement the audit, classify obligation-status
errors in the existing ablation traces, and produce a safety--autonomy plot.
Additional temperature-sampled repeats are optional, subject to a specific
unanswered question. These analyses will not retune the frozen held-out
methods. Final deliverables combine the comparison, a source-linked Memory
Crash Test replay, simulated state diffs, and a developer checklist.

The small synthetic, risk-enriched benchmark uses one model family and one
generation per context and router variant. Labels and audit rules reflect the
same authored policies, so separate implementations do not establish independent
label validity. Canonical cards and their trust are assumed; external lookups
are outside the memory budget. These results cannot certify production safety.
The design lesson is to validate action-specific proof at the tool boundary and
re-read current permissions and holds: an audit cannot recover an event absent
from every source it can access.
